# 模型参数与生成进度合同

模型参数由具体渠道的能力配置、已安装插件合同和协议校验共同决定。同名模型通过不同渠道接入时，可以有不同的尺寸、质量、数量和参考素材限制；界面必须读取所选线路的有效配置。

本页区分三类依据：**已配置**是开发环境只读目录中的声明，**协议约束**是仓库执行路径实际校验或编码的合同，**供应商依据**是已收录的公开文档。目录能证明配置存在，离线测试能证明请求和校验行为；二者都不证明账号权限、上游实际可用范围、输出质量或收费结果。

## 参数来源与覆盖顺序

| 层级                        | 作用与边界                                                                                                                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 插件 `imageParameters`      | 声明参数名称、类型、枚举、范围、步长、默认值、适用模型及请求绑定。管理员可缩小范围，不能突破声明的枚举、上下限或步长。                                                                         |
| 渠道模型 `capabilityConfig` | 保存实际开放能力。前端 `modelCapabilityConfigFor` 按渠道与模型选择配置，缺省部分才使用协议回退。不能用另一个渠道的同名模型覆盖它。                                                             |
| 图片参数投影                | 存在 `image.parameters` 时，尺寸、分辨率、质量、透明背景和数量均由该 schema 投影，旧能力字段只作为执行视图。旧配置首次解析到插件 schema 时，枚举取允许值，数量上限取原配置与插件上限的较小值。 |
| 工作流声明                  | 工作流的字段、选项和默认值用于推导其能力；工作流的分辨率和比例不被普通模型的固定列表替换。                                                                                                     |
| 节点选择                    | 用户显式值必须属于当前有效能力。切换模型时只保留仍合法的值，缺省值取当前模型默认；提交前仍须严格校验。                                                                                         |
| 服务端准入与协议            | 服务端重新检查能力、输入素材及组合限制，随后按插件绑定编码请求。界面可选不等于协议已经接受，更不等于供应商已生成成功。                                                                         |

配置解析入口为 `web/src/lib/model-capabilities.ts:modelCapabilityConfigFor`、`web/src/lib/image-parameters.ts`，服务端对应 `backend/internal/app/model_capability.go:NormalizeModelCapabilityConfigForModel`、`backend/internal/app/image_parameters.go` 和 `backend/internal/protocol/image_parameters.go:ResolveImageParameters`。

`providerDefaults` 属于供应商扩展参数的默认值，用户显式 `metadata.providerOptions` 覆盖对应默认值；服务端按实际选定线路合并、校验并冻结到任务。它不绕过尺寸、数量、素材或协议校验。已有任务继续使用快照，新任务和切线才使用新线路默认值，详见 [HTTP API 合同](/docs/backend/http-api)。

### 尺寸、分辨率与质量

- `size` 可以表示像素尺寸或比例，语义取决于 `encoding` / `size.parameter`；不能把 `16:9` 直接当成像素宽高。
- `imageResolution` 表示模型声明的分辨率档位；档位名称不限于 `1k/2k/4k`。精确像素由所选档位的 `size.presets` 或协议决定。
- `quality` 表示该协议的质量字段。旧 Gemini 合同曾用它承载分辨率，不应据此把所有模型的质量当作分辨率。
- `count` 表示当前请求的数量。插件能接受的上限、管理员开放的上限及默认数量是三个不同值。

通用图片回退中的 15 张输出、16 张参考图及大范围尺寸列表只是平台初始化值，不能作为任意模型的供应商能力证明。原生 Gemini 的旧前端回退曾允许 4 张，但当前 `google-gemini-image` 插件 schema 的 `count.max` 为 1；解析 schema 后使用较小上限。Grok 与 Agnes 的插件数量上限也不应直接替换管理员设置的单张限制。

修复后的 Wangsu Gemini manifest 优先读取独立 `resolution`，只兼容旧字面 `quality=1k/2k/4k`，普通 `low/medium/high` 不映射分辨率。前后端报价将旧 Gemini 价格档与明确分辨率对齐，旧字段不覆盖新选择。`wangsu-chat-image` 只有 Gemini 型号发送 `eca_image_config`；`qwen-image-edit` 不接收该配置。以上行为需部署新版代码和插件。

尺寸自定义开关只表示平台允许输入，不能证明供应商接受任意正方形、比例或像素。尤其 Liblib 的 `4k` 分组是管理员维护的精确尺寸集合，不是供应商原生 `resolution=4k` 参数。

### Liblib 的额外约束

`backend/internal/protocol/builtin_liblib.go:ValidateLiblibRequest` 在上传、排队和计费前校验：

- `family` 为 `f1` 或 `sd`，模板必须是真实有效 UUID；SD 还要求 checkpoint UUID、非负整数采样器及非负 CFG。步数为正整数，种子为 `-1` 或非负整数。
- 输出宽高每边为 **1–4096 的整数**，上限只代表宿主安全与请求合同，模板可能有更窄范围。尺寸依次取统一输出宽高、成对供应商 `width/height`、明确的像素尺寸字符串。
- 协议允许单次最多 **4** 张，开发目录当前只开放 **1** 张。缺省数量为 1，不能用协议上限改写管理员配置。
- 一张普通参考图切换为图生图，需要 `denoisingStrength` 为 0–1；控制图独立传入，不改变文生图/图生图判定。
- SD/SDXL 局部重绘要求独立原图和蒙版，真实像素尺寸相同；`f1` 当前不声明局部重绘。Canny 最多 4 组。

完整输入角色、蒙版和结果合成合同见 [结构控制与 Liblib](/docs/backend/controlnet)。

### 协议还会拒绝的组合

- **Hailuo 10 秒通常只接受 768P；Hailuo 02 首帧图生允许已实测的 512P/10 秒。** 该例外需新版宿主和插件，1080P/10 秒仍拒绝。Hailuo 采用首尾帧输入，不接受普通多模态参考素材。
- Veo 3.1 不在本轮开发目录内，但仓库合同已明确：参考图最多 3 张，必须为 `16:9`、8 秒，与首尾帧互斥；单独尾帧必须同时提供首帧。
- `wangsu-openai-videos` 也不在本轮开发目录内；它使用独立 multipart 合同、4/8/12 秒、720p、横竖比例及最多一张首帧，不能套用网宿多模态参考输入。
- Seedance 上游适配器虽能保留 `seconds=-1`，平台时长与计费合同要求正数，界面不开放自动时长。

组合约束由 `backend/internal/app/model_capability_wangsu.go:validateWangsuVideoTask` 和 `plugin-packages/generate-wangsu.mjs` 的声明式 validations 执行；平面枚举并不意味着任意笛卡尔组合都可用。协议路径及官方来源见 [Wangsu 渠道协议](/docs/backend/wangsu)。

Hailuo 02 的 `image_to_video + 10 秒 + 512p` 已通过供应商直调验证任务完成；本地宿主和插件已修正原先误拦截，待发布后验收应用全链路。价格档未修改。

## Tripo 3D 使用独立能力合同

Tripo 不属于上述渠道模型表。当前代码仅开放 H3.1、H3.0、H2.5 的文本、单图和多视图生成；不能从图片模型的尺寸、分辨率或质量控件推导 3D 参数。

| 固定模型版本            | 标准几何面数上限 | 精细几何面数上限 | 高级参数             |
| ----------------------- | ---------------- | ---------------- | -------------------- |
| `v3.1-20260211`（H3.1） | 150 万           | 200 万           | 支持                 |
| `v3.0-20250812`（H3.0） | 100 万           | 200 万           | 支持                 |
| `v2.5-20250123`（H2.5） | 50 万            | 不开放精细几何   | 不开放 H3.x 高级参数 |

`backend/internal/model3d/types.go:ValidateParameters` 还要求 PBR 依赖纹理；`fast` 纹理必须使用 `v3.5-20260815`；去光照依赖该纹理版本；无纹理时不能提交纹理质量、种子或对齐参数。四边面上限为 15 万；低多边形模式为三角面 500–20000、四边面 500–10000。面数省略表示自适应，不能用 0 代替省略。

文本提示词最多 1024 字符、负面提示词最多 255；单图和多图不接受文本提示词及内部图片种子。多视图需要正面且合计 2–4 张图片。当前模型、允许模式和默认模型仍由独立 3D 配置限制，代码支持不等于该环境已开放。官方来源、已知文档差异和收费边界见仓库 `docs/design/model3d-api-research.mdx`。

## 真实供应商进度与平台阶段

任务详情、任务摘要列表及 3D 任务视图提供可选 `providerProgress`，表示当前供应商明确返回的生成百分比。没有该字段表示当前没有可展示的真实百分比，界面展示 `status` / `stage` 对应的排队、生成、保存等状态。

- `providerProgress=0` 是有效值，不能用真假判断丢掉它；有效展示范围为 0–99。
- 供应商未返回、数据非法、返回 100 但结果尚未交付、任务正在保存或已经终止时，省略 `providerProgress`。
- 旧 `progress` 还可能承载平台内部调度数值，媒体界面不能再将它作为真实供应商百分比，也不能按等待时间生成百分比。
- 供应商生成完成不等于平台结果已就绪。下载、上传、素材登记等保存阶段显示“正在保存”；结果完成登记后才进入成功状态。

声明式协议在 `response.progress` 显式声明 `{ path, scale }`，例如 `{ "path": "task.progress_percent", "scale": 100 }`。`scale` 只接受 1 或 100，分别表示 0–1 比例和 0–100 百分数。没有声明时只报告状态；HTTP 日志层不再递归搜索形似 `progress` 的字段，也不根据数值大小推测单位。

官方插件包随代码一同发布；后端启动时从官方目录刷新 manifest 和包校验值，并保留管理员的启用状态。因此部署必须包含本轮更新的 `.yingce-plugin` 包。自定义包或仍使用旧包的环境如果没有声明 `response.progress`，继续只显示阶段，不推测百分比。

| 协议 / 运行时                                                            | 已确认的响应字段与单位         | 展示依据                                                                                      |
| ------------------------------------------------------------------------ | ------------------------------ | --------------------------------------------------------------------------------------------- |
| OpenAI Videos（协议 ID `newapi`）                                        | `progress`，0–100              | [官方查询接口](https://developers.openai.com/api/reference/resources/videos/methods/retrieve) |
| `novita-video`                                                           | `task.progress_percent`，0–100 | [官方任务结果](https://docs.novita.ai/api-reference/model-apis-task-result)                   |
| `kacang-midjourney-special`、`kacang-midjourney-v7`、`kacang-midjourney` | `progress`，百分数字符串       | 已收录的 [Kacang 文档](https://console.prompt-hubs.com/docs) 与对应插件接口说明               |
| `runway-image`、`runway-video`                                           | `progress`，0–1                | [官方 API](https://docs.dev.runwayml.com/api.md) 的任务查询合同                               |

| Liblib WebUI                                                             | 不启用百分比                   | 已收录文档将进度字段标为暂未实现，只按任务状态展示                                            |

仓库当前 84 项图片/视频协议贡献中，7 项声明了百分比，56 项异步协议只提供阶段，21 项同步协议只展示处理状态；Tripo 使用独立运行时。协议贡献数量不等于供应商数量，同一供应商可以包含多个协议。

以上字段映射确认了如何解释供应商数据，没有执行新的真实付费生成来验证每个账号的返回频率、精度或单调性。供应商可能长时间不更新或不返回百分比，界面仍以阶段继续等待。

进度只来自原任务的查询结果。断线恢复继续查询原任务，不能为获得新的进度重新创建付费生成任务。Tripo 继续保留独立保存阶段与原任务恢复合同。

## 验证边界与后续核验

首次矩阵来自代码、插件 manifest、既有专题和脱敏目录对照。公开来源包括 [网宿模型目录](http://doc.model-store.ai/ai-gateway/model/support-doc)、[Liblib 官方 API 使用说明](https://resonate.feishu.cn/wiki/UAMVw67NcifQHukf8fpccgS5n6d)、[Liblib SDK 图生图示例](https://github.com/gravitywp/liblib-javascript#image-to-image) 与 [Tripo H 模型接口](https://developers.tripo3d.ai/zh/docs/generation-image-to-model/standard)；其中 Liblib、Tripo 为既有收录依据，Wangsu 后续核查范围见专题。

本页首次梳理没有新增付费调用；后续 Wangsu 专项的 7 次真实调用及官方依据见专题。仍需确认 OpenAI 兼容渠道的通用 15 张输出与 16 张参考图配置、Kling 其他可选参数、Seedance 2.0 参考视频数量，以及 Liblib 各模板的真实尺寸范围。真实调用仅证明该组账号、模型和参数，不扩展为所有组合的验收结论。

新增或修改能力时，应分别验证模型切换保留合法值、越界值在提交前被拒绝、服务端准入与价格选择使用同一组值、协议请求字段正确；涉及真实进度时，还应区分供应商阶段与平台保存阶段。部署后的浏览器与真实供应商验收状态继续维护在 [待测试清单](/docs/progress/pending-test)。
