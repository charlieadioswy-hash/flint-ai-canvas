# 图片合规检测

图片节点提供手动“合规检测”入口。用户点击后，后端执行当前生效配置中的全部检测项目，将本次结果汇总为一份报告。生成图片、恢复画布、查看旧报告和公开分享均不会自动发起检测。

## 用户操作

1. 在已有图片的节点工具栏点击“合规检测”。图片需绑定当前用户可访问的原始资源；仅有本地图片时，先保存原图资源再提交检测，不检测缩略图。
2. 查看排队、运行及最终报告。节点保留结果摘要，报告面板展示统一风险等级、风险标签、检测时间和是否仍适用于当前图片。
3. 完成后可明确点击重新检测，创建新的检测批次。查看报告、轮询进度和刷新页面只读取结果，不再次提交检测请求。

画布用户无需选择平台、地域或检测项目；报告也不返回这些后台配置。公开分享仅展示画布中保存的报告快照，不提供提交检测或查询私有报告的能力。

分享响应通过 `sharedImageModeration` 返回独立的展示摘要，仅在保存的报告身份、报告资源 ID 与图片原始资源一致时公开。摘要保留状态、风险等级、标签、说明、时间及保存时的 `isCurrent`，不包含检测批次 ID、内容版本、平台配置或原始响应；读取分享不重新计算报告是否过期。图片地址改写为分享资源路径后，前端按资源 ID 关联摘要，轮换分享链接不会丢失报告，换图后不能沿用旧结论。

图片原始资源须处于 `ready`，大小不超过 20 MiB。格式与尺寸由后端在创建批次和实际执行前校验；不支持的图片直接拒绝，不请求检测平台。批次同时绑定原始字节 SHA-256 和资源身份快照，排队期间替换图片会终止该批次，旧结果不能视为新图片的结论。

## 后台配置

管理入口为 `/admin/settings/image-moderation`。可保存多个 Provider 配置，目前实现阿里云，支持上海与北京地域。平台适配与统一汇总位于独立的 `internal/moderation` 域包，新增平台需要实现适配器，不要求修改画布用户合同。

阿里云首期可配置的检测项目为：

| 项目 | 服务标识 | 说明 |
| --- | --- | --- |
| AIGC 图片内容风险 | `aigcCheck` | 返回图片内容风险等级与风险标签 |
| 疑似侵权元素 | `aigcViolationDetection` | 公测服务，需对应阿里云账号具备服务权限；不等同于法律结论 |

每次保存追加不可变的配置版本，包括地域、项目、凭据和调用控制。保存新版本后，原生效版本继续使用；管理员须单独点击“设为生效”，才影响之后创建的批次。同一时刻只有一个 Provider 的一个配置版本生效。

切换生效版本或停用检测采用 `policyRevision` 条件更新，陈旧页面操作返回冲突，管理员须刷新核对。停用仅阻止新批次，在途批次继续按创建时的配置执行。当前生效 Provider 需先停用或切换到其他 Provider，才能禁用或归档；归档保留旧配置和报告。

首次配置须同时填写 AccessKey ID 和 Secret。编辑时两项同时留空表示沿用旧凭据，更换时须同时填写两项。服务端使用既有设置密钥机制加密保存，读取接口只返回“是否已配置”；浏览器不回显旧凭据，审计记录不包含凭据正文。

“配置校验”只检查配置结构、支持的服务与凭据是否能够解密，不向阿里云发请求，不验证账号权限或服务开通状态。保存、切换生效版本和归档也不调用检测平台。远程服务是否可用，须通过有必要的、明确次数预算的真实检测验收。

## 统一汇总规则

一份报告只汇总一次手动操作创建的批次，包含配置的全部项目。再次检测创建独立报告，历史风险不累加到新报告，也不平均不同检测项目的置信度。

| 本批次结果 | `status` | `overallRisk` | 用户含义 |
| --- | --- | --- | --- |
| 全部项目成功且均无风险 | `completed` | `none` | 当前图片未检测到风险 |
| 全部项目成功，至少一项有风险 | `completed` | `low`、`medium` 或 `high` | 取已知风险中最高等级 |
| 部分项目失败，其余无风险 | `partial` | `unknown` | 检测未完整，不能显示无风险结论 |
| 部分项目失败，其余有风险 | `partial` | 已知最高风险等级 | 显示已发现风险，同时说明检测未完整 |
| 没有任何有效项目结果 | `failed` | `unknown` | 检测失败，不能回退为旧的无风险报告 |

相同稳定标签代码去重并保留更高风险等级；显示顺序按风险等级和代码确定。未知风险等级或无法解析的响应按失败处理。

“最新报告”按批次创建顺序选择，包含排队、执行中、部分失败和失败批次，不按完成顺序覆盖。`isCurrent` 同时检查资源身份、是否为最新批次以及当前生效配置版本；图片变化、配置切换或停用服务后，旧报告作为历史结果保留，不能继续标注为当前有效。

## 调用控制与恢复

- 同一用户、原图内容和配置版本已有排队或执行中的批次时，重复点击复用在途批次，返回 `reused: true`。终态报告不作为新点击的缓存；明确复检会创建新批次。
- `minIntervalSeconds` 限制同一用户创建新批次的最小间隔，适用于不同图片；在途批次复用先于该校验。间隔内的新批次被拒绝，不自动延迟补发。
- `maxCallsPerDay` 按平台全局、UTC 自然日统计，各检测项目分别占一次调用预算；切换 Provider 不重置已用次数。Worker 在每个项目开始前事务预占次数，失败或结果不确定的已开始调用不会退还预算。该计数是保守的调用控制，不能当作阿里云账单。
- 单项检测超时范围为 5–120 秒。SDK 检测请求关闭自动重试，不自动切换平台。结果丢失时前端只查询最新批次，不自动重发创建请求。
- Worker 使用持久队列与租约。进程中断后，已经开始但结果不确定的项目标记失败，不重新请求平台；尚未开始的项目可由后续 Worker 继续执行，最终仍形成完整或明确不完整的汇总报告。
- 排队和执行中的检测构成资源引用，用户删除、管理员删除及资源清理需保留原图，直到批次结束。

阿里云适配器通过官方 Green SDK 取得临时上传凭据，将原图上传至受限的阿里云 OSS，再调用 `ImageModeration`。同一批次多个项目复用一次上传；临时密钥、签名地址和原始错误不回传用户。出站访问使用既有 SSRF 防护，并拒绝签名请求重定向。
