## 入口与数据归属

`/model3d` 是登录后的独立任务工作台。入口点击、参数编辑、生成、刷新和预览都不创建画布。生成结果通过现有 Resource 与模型素材保存，候选版本通过任务关联。画布内 3D 节点及其恢复、分享继续使用原合同。

后台 `/admin/settings/model3d` 管理唯一生效的服务商、模型、模式与策略修订。独立页复用这套能力，不额外保存密钥或单独指定供应商。

## 输入、贴图质量与重新生成

单图和多视图的各个图片槽位支持点击选择与拖拽上传，沿用同一套文件类型、大小、尺寸和归属校验。每个槽位每次接受一张图片，多文件会提示分别上传；上传期间禁止替换当前输入，失败后可重试。

独立页支持标准、高清和 8K 贴图，8K 对应 Tripo 的 `texture_quality: "extreme"`，表示贴图分辨率，不是几何面数。仅对声明支持高级参数的模型开放，白模和不支持的模型不提交此字段。确认弹窗显示选定质量，并提示 8K 的耗时、文件大小、预览显存和服务商实际计费。

预览区与历史版本卡片提供「修改后生成新版本」：先将所选任务的输入复制到编辑区，文字模式可编辑提示词和参数，图片模式可替换参考图和修改参数；此操作不自动生成。修改完成后点击「确认并生成」，确认弹窗中的快照才用于新请求。只切换历史版本不覆盖正在编辑的输入。

每轮重新生成分配新的 `groupId`，每个候选分配新的 `requestId`，保留原任务及其模型资源。历史列表区分创建时间与本批候选序号；不把候选序号当作跨批次版本号。刷新通过服务端历史恢复新旧版本，继续同步已受理任务，不创建画布或覆盖旧产物。此入口是使用新输入重新生成模型，不是对原模型局部编辑或重新贴图。

## 任务 API

- `GET /api/model3d/capabilities`：读取开放能力。
- `POST /api/model3d/tasks`：创建任务，独立入口显式传 `scope: "standalone"`，省略 `canvasId` 与 `nodeId`；带画布标识的独立请求会被拒绝。省略 scope 时保持原画布合同。
- `GET /api/model3d/tasks?scope=standalone&limit=30`：按当前用户与独立归属查询，使用 `cursor` 继续读取，返回 `{tasks, nextCursor?}`。`limit` 范围 1–100；`activeOnly=true` 用于恢复历史页之外仍在执行的任务。排序为创建时间倒序、ID 倒序。
- `GET /api/model3d/tasks/:id`、`GET /api/model3d/requests/:requestId`：读取已提交任务或核实同一请求。
- `GET /api/model3d/tasks/:id/segmentation`：按本人已成功的独立原始模型查询可复用拆分；无结果返回 `null`，不会创建任务或调用供应商。
- `POST /api/model3d/tasks/:id/recover`：仅恢复允许恢复的原任务交付，不重新创建模型。

每个候选有独立 `requestId` 与 `sourceFingerprint`，同时传入同一 `groupId` 和对应的 `candidateIndex`、`candidateCount`。这三个字段可一起省略；传入时必须齐全，`1 <= candidateIndex <= candidateCount <= 4`。相同请求 ID 与相同正文复用原任务，变更正文或归属会冲突。

任务投影包含 `scope`、`requestId`、`prompt`、`parameters`、`imageResourceId` 或 `views`、候选关联及原有状态、错误和结果字段，用于历史恢复和显式复用参数。独立任务的客户端上下文没有画布或节点绑定。任务列表与资源仍由后端校验当前用户归属。

## 进度与提交恢复

页面自动同步后台任务，刷新或重进后继续观察原任务，不重新执行生成。活动任务与已加载历史分开恢复，避免分页漏掉仍在运行的任务。离开页面取消浏览器观察，不取消已受理的后台任务。

百分比只取 `providerProgress`，真实的 0 可显示；缺失、非法值、供应商 100、结果保存和终态不显示旧百分比。供应商生成完成后继续显示文件保存阶段，资源与素材登记完成后才显示完成。

查询的暂时网络错误允许退避；提交失败且结果不确定时按原 `requestId` 查询，不自动重发 POST。部分候选已受理时保留它们，不用整轮重新提交替代恢复。每个候选分别占用实际任务预算，仍受既有并发、平台日预算和存储限制。

## 多格式预览与导出

共享预览器支持 GLB、GLTF、FBX、OBJ 和 STL，并限制为自包含文件。不会按模型内声明请求任意外部贴图或几何地址；外置依赖须先在建模工具中打包为 GLB。GLB 保留 Meshopt 解码支持。页面同时提供本地模型预览，本地导入不会创建任务、画布或云端素材。

预览默认显示地面网格及随相机旋转同步的 XYZ 方向指示，可分别关闭；方向键或拖拽可旋转，R 或「重置视角」恢复初始视角。网格位于归一化模型底部，仅作方向参考，不代表实际尺寸，不写入模型或导出文件。静态或暂停时按需渲染，只有用户播放动画且预览可见时持续绘制；切换标签、移出可见区域或关闭预览会停止动画帧。

原文件下载走既有资源访问合同。额外导出在浏览器内转换为 GLB、GLTF、OBJ 或 STL；OBJ/STL 仅含几何，GLB/GLTF 可保留解析出的材质。FBX 与 ABC（Alembic）由后端按需启动 Blender 转换，不调用供应商 API 或收取供应商转换积分。原文件始终保留；原生 FBX 的同格式下载直接使用原文件，不启动 Blender。

FBX 的 Phong／Lambert 材质转换为 GLB／GLTF 时保留发光强度，包括显式的零值，避免白色发光颜色配合零强度的原模型在转换后发白。骨骼与动画继续随 GLB／GLTF 保存，不修改源文件。

资产库的模型卡片菜单、素材档案和画布 3D 节点共用下载弹窗，可选择原文件、GLB、GLTF、OBJ、STL、FBX 或 ABC；独立 3D 页保留下载格式菜单。画布节点默认下载原文件。资产库始终保存上传或生成时的原始文件，下载转换不覆盖素材，也不重新生成模型。原文件及与原格式相同的选择使用资源下载直链；GLB、GLTF、OBJ、STL 复用浏览器转换，FBX、ABC 使用下述异步导出。源格式无法识别时保留原文件下载，转换仍受自包含依赖与 128 MiB 文件限制。关闭下载弹窗、切换素材或账号、离开页面会中止当前下载准备并取消后台导出，旧操作不得在取消后保存文件。

### FBX 与 Alembic 异步导出

- `GET /api/model3d/exports/capabilities` 返回 `{ available, formats }`。格式选择仍显示 FBX／ABC，点击下载时检查后端可用性；Blender 不可用会给出提示，原文件及浏览器导出仍可使用。
- `POST /api/model3d/exports` 接收 JSON 资源引用，或 multipart 本地文件。字段为 `requestId`、`resourceId` 或 `file`、`sourceFormat`、`fileName`、`format: "fbx" | "abc"`，以及可选的 `animation`、`fps`；帧率省略时为 30。同一请求号及相同输入复用原任务，不能用同一请求号更换输入。
- `GET /api/model3d/exports/:id` 查询本人任务；`DELETE /api/model3d/exports/:id` 或 `DELETE /api/model3d/exports/by-request/:requestId` 取消。提交响应丢失时仍可按请求号取消，不能因浏览器停止轮询而留下继续工作的转换。

导出使用当前用户选中的原始资源版本或显式上传的本地文件，不从预览器中取归一化、爆炸分离或隐藏部件后的场景。输入与输出均不超过 128 MiB，后端核实资源所有权、就绪状态及存储配额，只接受自包含的 GLB、GLTF、FBX、OBJ、STL，不跟随任意外部文件或 URL。只有显式点击导出时才上传本地模型；该文件作为普通本人资源保存并计入配额，取消不会自动删除源资源。完成后登记新的下载资源，不覆盖原始模型；排队、运行与取消沿用已有任务基础设施，转换不占用 Tripo 任务或付费提交记录。

含 Meshopt 几何压缩的 GLB／GLTF 由浏览器从源文件重新解析，导出未压缩 GLB 派生文件再上传转换，原文件保持不变；不使用预览场景的归一化变换。此路径保留解析器支持的几何、材质与动画，不能视为所有扩展的无损直通。Draco 压缩暂不支持，需先在建模软件中导出未压缩 GLB；直接调用后端 API 提交 Meshopt／Draco 压缩输入也会明确失败。

FBX 尽量保留网格、UV、材质贴图、骨骼与动画，跨格式导出不承诺所有 PBR 材质和扩展无损。多个对象共同参与多个动作时，FBX 的全部动作导出会明确拒绝，需先在建模软件中整理动作；不能承诺任意多动作模型都能完整转换。ABC 导出选定动作的逐帧几何缓存，保留 UV、法线与面集；不保留可编辑骨骼、蒙皮控制器或完整着色器。ABC 多动作模型必须明确选定一个动作，零时长的单关键帧姿态也可选择，不能将不同片段拼成同一缓存；静态模型导出静态几何。ABC 不进入网页模型预览，继续通过原模型查看外观。通用任务列表不将 FBX／ABC 导出文件当作图片预览。

任务重领时复用已登记的就绪输出；保存中断留下的未完成资源不会阻塞后续导出。每次执行写入独立输出，校验当前任务租约后登记为可恢复结果，旧执行不能覆盖新结果；未使用的副本按现有资源生命周期清理。

生产与开发后端镜像内置无 GUI 的 Blender，只有导出时才启动子进程，每次转换最长 10 分钟，集群通过租约将转换并发限制为 1；没有常驻 Blender 服务。宿主机开发需安装具备 FBX 和 Alembic 支持的 Blender 4.x，`CANVAS_BLENDER_BIN` 可指定可执行文件的绝对路径，留空时在 `PATH` 中查找 `blender`。容器内该变量同样表示容器内路径。能力接口检查可执行文件是否存在，模型兼容性与输出质量仍以实际转换和目标软件回读为准。

「帮我想想」提供模型描述示例，用户也可选择文本模型显式生成提示词；这只创建文本任务，不自动创建 3D 任务，采用描述后仍需确认 3D 参数才开始生成。

## 部件拆分、补全、绑骨与动画

在独立页选择已完成版本后，预览下方的「模型后续处理」按来源类型开放操作。新处理需单独确认，生成独立任务；拆分优先复用同源旧任务。产物为新模型资源和资产，不覆盖来源，不创建画布。本地导入仍仅用于预览，暂不支持对本地文件执行这些供应商操作。

| 操作 | 来源 | 参数与产物 |
| --- | --- | --- |
| 部件拆分 | 本人原始生成任务 | 几何 v1 或语义 v2（Beta），v2 可选粒度和连通区域；结果为包含多个部件的 GLB |
| 部件补全 | 已成功拆分任务 | AI 补齐缺失几何或快速封口，可选全部或指定部件；名称须来自该结果的 GLB 节点 |
| 绑骨检查 | 本人原始生成任务 | 返回是否可绑骨及骨架类型，作为独立任务保存；不创建模型资产 |
| 自动绑骨 | 可绑骨检查结果 | 服务端解析被检查的原模型。v3.0 / v2.5、匹配检查结果的骨架类型、人形命名规范、GLB / FBX 输出 |
| 动画 | 已完成绑骨任务 | 匹配骨架的预设动作、是否原地运动、GLB / FBX；每个动作独立保存新版本 |

点击「部件拆分」或「查看或拆分部件」先查询同一原始模型的历史拆分。已有成功结果直接选中；正在执行、提交结果未知或可恢复保存失败时打开原任务的进度／恢复入口，不重新调用供应商。没有可复用任务才显示确认并发起新拆分，确定失败的任务可显式重试。服务端在事务锁内再次去重，不同请求号并发点击也只创建一个任务；已有结果不受当前拆分参数变化影响，也不要求当前服务商仍启用。

复用 POST 可以返回原任务的 `requestId` 和 `sourceFingerprint`，前端只对同源拆分的本地待提交项接受这种身份替换。每个已受理的新请求号都在 `model3d_requests` 中保存当前用户、请求摘要和原任务的关联；快速复用及事务内并发复用均在返回前写入。响应丢失后按本次请求号查询，即使原任务随后失败或取消，也返回其最终状态并结束本地未知提交占位。请求恢复不按来源猜测其他拆分、不自动重发 POST；确定失败后只有显式新请求号才能创建重试。同一请求号携带不同正文仍返回冲突，读取失败不视为“尚未拆分”，切换任务或账号后忽略迟到结果。

v3.0 与 v2.5 使用同一组新预设：双足可待机、行走、奔跑等；四／六／八足使用各自的行走动作，蛇形／水生使用各自移动动作。鸟类和其他骨架暂无已核实的公开预设，保留绑骨和下载，界面不提供无效动作。当前没有接入 v1 的旧版 90 多个动作、批量动作或自定义动作上传。

处理仍使用 `POST /api/model3d/tasks`，正文为 `requestId`、`sourceFingerprint`、`scope: "standalone"`、`expectedPolicyRevision`、`processing`。不与 `mode`、`parameters`、图片或候选参数混用。`processing.sourceTaskId` 只接受平台内本人任务；后端核实完成状态、来源步骤、资源归属／版本、服务商实例及凭据一致，再解析上游 ID。结果的 `processing` 保存父任务和操作参数；检查结果单列 `rigCheck`，只有模型产物返回 `result`。

```json
{
  "requestId": "unique-processing-request",
  "sourceFingerprint": "processing-snapshot",
  "scope": "standalone",
  "expectedPolicyRevision": 1,
  "processing": {
    "operation": "complete",
    "sourceTaskId": "owned-segmentation-task",
    "completionMode": "quick_cap",
    "partNames": ["tripo_part_0"]
  }
}
```

处理复用同一提交检查点、用户请求幂等、日任务预算、队列与存储恢复。每个新操作（包括检查）占用一次平台日任务计数，复用已有拆分不新增计数；供应商费用使用后台配置的 Tripo 账号，未在此增加本站积分售价。模型任务 ID、签名地址和密钥由服务端处理；账号变更后拒绝跨账号创建新处理任务，历史结果仍可读取。结果不明只查询原请求，不自动再次付费提交。

拆分／补全结果可按节点显隐。没有动画且识别出多个部件时提供「分离展示」：按原始空间结构向外拉开部件间隙，保留各部件之间的相对方向及自身尺寸、朝向，形成爆炸视图。显示时保留当前观察方向并自动取景；「还原组装」恢复各部件原始位置和分离前视角。显隐与分离状态仅影响预览，下载仍保留完整产物和原始组装位置。共享查看器支持骨骼显隐、动作选择、播放／暂停、拖动进度与 0.5–2 倍速，初始不自动播放。GLB／GLTF 转换保留解析出的骨架与动画；OBJ／STL 为静态几何，不包含骨骼或动画。供应商原生 FBX 直接下载，其他来源可使用后端 FBX 导出；ABC 仅保留烘焙后的几何运动。

官方合同和当前边界见 `docs/design/model3d-api-research.mdx` 的后处理章节；真实供应商验证的已测组合、已知限制与未测范围见 [待测试](/docs/progress/pending-test)，离线通过不代表所有模型或参数组合已验收。
