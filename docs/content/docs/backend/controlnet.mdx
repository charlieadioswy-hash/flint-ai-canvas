# 画布结构控制与 Liblib

「结构控制生图」复用图片节点、模型选择、持久任务、结果资源和图片批次。它通过独立的控制图引导画面结构，再用输出蒙版确定最终图片的可见范围。Liblib 的设置分为 Control Type（控制类型）、Preprocessor（预处理器）和 Model（控制模型），三者与生成底模共同决定有效参数，不再固定为 Canny。

代码和模拟协议测试可在没有 Liblib 账号的情况下运行。模板、基础模型与控制模型的实际组合、生成质量及供应商费用仍需部署者配置账号后联调；测试图片和接口桩不能证明真实模型效果。

## 使用入口与图片角色

### 异形屏快捷创作

从工作台侧栏进入「异形屏创作」（`/screen-creation`），上传屏幕蒙版，选择「文生图」或「图生图」，再输入画面描述。图生图必须上传内容原图，并可在高级设置中开启「蒙版重绘」。生成方式与 Control Type 分别设置。页面提供原始蒙版、有效区域和结果预览，以及透明背景的转角屏示意。「高级设置」默认折叠，提供类型、预处理器、控制模型及对应参数。模型候选只保留已启用、可用并配置了兼容 ControlNet 能力与生成默认参数的系统渠道模型，不要求必须支持 Canny。

Liblib 文生图在后台已开放 Inpaint 且存在兼容控制模型时，默认选择 Inpaint；否则沿用当前模型实际可用的控制类型。仅通过默认控制模型 UUID 推断底模的配置同样适用，选择 Inpaint 时保留该推断依据。SDXL 优先采用官方推荐的 `inpaint_global_harmonious` 与 `segmentation_mask_brushnet_ckpt_sdxl_v1`，预处理器没有额外滑块参数。控制强度、开始时点、结束时点为 `1 / 0 / 1`，完美像素关闭，与公开 Liblib WebUI 的新控制单元设置一致；处理器与模型采用官方目录推荐组合，未将 API 示例称作网页默认。高级设置提供完美像素开关。控制模式保持均衡，缩放仍使用完整坐标拉伸，与普通 WebUI 的裁剪默认不同，以保证屏幕结构图与输出蒙版对齐。

新建场景、文生图切换模型及从图生图切回文生图时应用上述默认控制参数；切换模式不覆盖提示词、尺寸、采样或种子。重新点击已选中的文生图不会清除手动选择，恢复已保存场景保留原控制类型、参数与完美像素值。手动从其他类型切到 Inpaint 时采用 `1 / 0 / 1` 并关闭完美像素，清除前一预处理器的专有参数。「使用科幻跑车示例」只在当前类型为 Canny 时填入其轮廓调试参数，其他类型保留各自控制参数。

再次进入默认恢复当前账号最近更新的异形屏场景；登录用户按需读取云端场景摘要，未登录时从当前浏览器的本地场景恢复。点击「新建场景」才进入空白设置，进入页面本身不会创建画布；首次生成或打开完整画布时才保存场景。场景读取失败会显示重试提示，不将网络错误当作没有历史场景。异形屏内部画布不显示在自由画布列表，但仍可从「最近场景」或「打开完整画布」进入，已有素材与生成结果保留。

「最近场景」每页读取 40 条，可点击「加载更多场景」访问更早记录；下一页失败时保留已加载内容并提供重试。自动恢复前逐个校验候选场景，只跳过服务端明确返回 `404 / not_found` 的场景；网络、权限与服务错误保留重试提示。本地缓存和离线修改不会被删除，`revision: 0` 的未上传草稿仍可恢复。当前页候选均失效时继续读取下一页，不把分页之外的场景判为已删除。

新上传的屏幕蒙版只接收透明 PNG：屏幕内不透明、屏幕外透明，单张不超过 10 MB、宽高各不超过 4096 像素。示意图的棋盘格只表示透明背景，不能烘焙进上传图片。上传后保留原始彩色像素作为结构控制图，按透明度确定性派生白色屏内、黑色屏外的灰度蒙版；没有有效区域、没有透明背景或格式与尺寸不合要求时阻止使用。新上传不提供识别方式切换。历史场景保留原来的自动、彩色、亮度或透明度解释；页面提示「历史蒙版仍按原规则读取，替换时请上传透明PNG」，替换后应用新规则。

平台保存的原始 PNG 保持不变。向 Liblib 提交含透明像素的 Canny 控制图时，宿主先将透明背景确定性合成为黑底再上传，保留不透明区域的 RGB 与内部转角边界，避免隐藏在透明像素中的 RGB 影响边缘检测。此策略不依赖上游对 alpha 的解释，也不代表已经验证供应商的透明图处理效果。

「文生图」不提交普通内容原图；「图生图」将内容原图绑定为 `reference`。屏幕原图绑定为 `control-image`，派生蒙版绑定为 `output-mask`。未指定固定模板时，按显式生成方式选择渠道的文生图或图生图模板；管理员明确配置的固定模板优先。上传屏幕蒙版本身不会切换到普通图生图。切回文生图时清除内容原图与蒙版重绘开关，提交不再包含普通参考图、重绘 `mask` 或旧的重绘选项，ControlNet 和最终输出蒙版仍保留。Canny 约束轮廓与内部边界，不会把不同颜色绑定为独立区域提示词。

图生图高级设置中的「蒙版重绘」要求内容原图与屏幕蒙版像素尺寸完全一致，同时将派生灰度蒙版绑定为独立的 `mask`。当前支持启用蒙版能力的 Liblib SD / SDXL 图生图模型；能力或模板不满足时显示具体原因。原图、重绘蒙版、ControlNet 控制图与最终输出蒙版各自生效。重绘后仍执行输出蒙版合成，屏幕外输出纯黑；原图与蒙版的输入尺寸一致，不要求模型输出与输入像素数相同。这是本平台对 Liblib 图生图 API 的封装，不代表 Liblib 网页存在第二个独立 Inpaint 菜单。

Control Type 选择 Inpaint 时，快捷入口另将派生灰度蒙版绑定为该控制单元的 `control-mask`。这不会自动切换生成方式，也不会替代顶层局部重绘的原图与 `mask`。通用画布中需要单独选择该区域蒙版；这是本产品的提交约束，不能据此声称官方通用字段始终必填。

快捷入口创建三个标准图片节点：结构原图、派生蒙版、生成节点；添加内容参考图或重绘原图时增加第四个图片节点。派生蒙版始终有 `output-mask` 引用，启用局部重绘时另有 `mask` 引用。`CanvasProject.creationScene` 仅记录 `kind: "irregular-screen"`、版本、节点 ID 映射与蒙版识别模式；生成配置以生成节点的 `generationSpec` 为唯一合同，局部重绘状态从 `mask` 引用恢复，平台参数保留在该节点的 `providerOptions` 中。再次打开 `/screen-creation/:canvasId` 复用同一场景；更新输入和提示词时保留节点身份、已有结果、用户布局及不属于场景的画布内容，也可进入完整画布继续编辑。

控制原图与派生蒙版使用完全相同的像素尺寸和坐标。两种生成方式均可选择模型支持的同比例输出尺寸，优先使用已配置的像素预设，按管理员默认尺寸的像素规模排序；只有没有匹配预设且模型允许自定义时才沿用原始尺寸。仅容忍不超过 0.5% 的像素舍入比例误差，不选择明显不同的比例，也不裁剪或补边。内容参考图与重绘原图接收 PNG/JPEG，单张不超过 10 MB、每边不超过 4096；屏幕蒙版使用上述透明 PNG 规则。提交前仍须满足资源与协议校验。最终结果由后端使用派生蒙版合成为黑底 PNG，屏幕外为纯黑。

快捷入口的真实上传、报价、生成与刷新恢复需要单独验收，不能沿用普通结构控制节点的历史验收结论，见[待测试与用户验收](/docs/progress/pending-test)。

### 通用画布节点

在画布添加「结构控制生图」，选择声明了 ControlNet 能力的图片模型，绑定或上传控制图，选择 Control Type、预处理器与兼容控制模型，再输入提示词。模型显示官方名称，并可展开查看 UUID。普通参考图仍走现有图生图入口；控制图不会混入普通参考图数组。

首版画布入口选择明确的系统渠道或自定义渠道模型。逻辑模型隐藏供应商协议，目前无法可靠展示其平台专有模板参数，因此不开放给此节点；后端仍保留独立 `control_image` 能力合同，后续需补全逻辑模型的参数投影后再开放。

| 输入 | 用途 | 范围外处理 |
| --- | --- | --- |
| 控制图 | 通过 Canny 等预处理引导轮廓与空间布局 | 不保证范围外像素不变 |
| 控制区域蒙版 | 限定该控制单元施加引导的位置，黑底白区域 | 不保证范围外像素不变 |
| 局部重绘蒙版 | 与内容原图一起指定供应商的重绘范围 | 不承诺像素完全一致；异形屏最终还会合成黑底 |
| 输出蒙版 | 在图片生成完毕后，由宿主确定性合成黑底 PNG | 范围外输出纯黑 |

红、绿、蓝三个屏幕区域共用一幅场景时，结构图可直接使用示意图。通用节点的「非黑区域」输出蒙版会保留所有非黑像素，也包括白色边框；带白框的彩色示意图应先派生有效区域灰度蒙版。异形屏快捷入口的新上传则需先准备屏外透明的 PNG，彩色区域识别仅为历史场景保留。输出蒙版选择灰度模式时，白色保留、黑色遮挡、灰色按比例混合。

使用输出蒙版时，控制图与蒙版应来自同一画幅，宽高比必须一致。两者明确按完整画幅拉伸到生成尺寸；控制单元不能再选择居中裁剪或补边。屏幕实际像素映射、透视校准与裸眼立体效果不由蒙版合成自动完成。

## 参数与能力边界

节点最多配置四个控制单元；具体模型可声明更低上限。

| 通用字段 | 范围或含义 |
| --- | --- |
| `controlType` | Liblib 控制类别；明确选择类型后筛选预处理器与模型 |
| `preprocessor` | 官方目录中的预处理器标识，如 `canny`、`depth_leres`、`openpose_full` |
| `model` | 兼容当前类型、预处理器及底模的 Liblib 模型 UUID；Reference 使用空标识的 None 模型 |
| `strength` | 0–2 |
| `start`、`end` | 0–1 的采样进程比例，起点不晚于终点 |
| `pixelPerfect` | 按生成尺寸自动选择检测分辨率 |
| `controlMode` | `balanced`、`prompt`、`control` |
| `resizeMode` | `stretch`、`crop`、`fill`；启用输出蒙版固定为 `stretch` |
| `canny.resolution` | 64–2048，推荐起点 512 |
| `canny.lowThreshold`、`highThreshold` | 1–255，推荐起点 100、200 |
| `processorParameters` | 非 Canny 预处理器的专有参数；字段、默认值、范围与整数约束来自官方目录 |

节点提供可编辑的推荐参数，提交时冻结有效参数。推荐值仅是调试起点，不表示所有基础模型、控制模型与题材使用同一最优设置。

### Control Type 与联动目录

当前通用流程接入 Canny、SoftEdge、MLSD、Scribble/Sketch、Lineart、Depth、Segment、Normal、OpenPose、Tile/Blur、Reference、IP-Adapter、T2I-Adapter、Shuffle、Recolor、Inpaint、Instant ID 和 puLID。类型可用仍取决于管理员开放的预处理器、生成底模与控制模型目录，并非所有类型都适配每个底模。

目录依据 [Liblib 官方预处理器表](https://resonate.feishu.cn/wiki/UAMVw67NcifQHukf8fpccgS5n6d#share-Z2zjdfLzGoAJcrx0twhcLxb5nnJ)、[控制模型表](https://resonate.feishu.cn/wiki/UAMVw67NcifQHukf8fpccgS5n6d#share-VZ1odH3pbowJypxPP3Mc8cY2nic)及明确的专用示例维护。唯一源为 `backend/internal/protocol/controlnet_catalog.json`；Go 校验、前端生成文件和插件镜像保持一致。目录包含 64 个通用预处理器，以及禁用执行的主体参考专用条目；模型 UUID 合并为 119 个目录项，包含 None、Qwen Image 和专用流程记录，不表示这些记录都可在当前模板执行。

- 切换类型时选择该类型的预处理器、兼容模型与默认参数，保留控制强度及起止时点，移除旧预处理器专有参数。切换预处理器时优先采用官方建议模型；建议列表不是排他的兼容白名单。
- 模型依次按 Control Type、SD 1.5 / SDXL / F.1 底模、明确的预处理器限制和管理员白名单筛选。管理员可登记额外 UUID 的名称、底模和类型，不能覆盖已知官方 UUID 的兼容关系。底模不能从用户当前选中的控制模型反推；显式底模与已知 checkpoint 或 `family` 冲突时拒绝提交。
- `None` 表示不预处理，保留明确的控制类型，仅用于官方列出的已处理线稿、深度图、骨骼图等输入；`Invert` 只用于官方线稿模型组合，不开放给任意类别。Reference 使用 SD 1.5 与 None 控制模型，不能套用 Canny UUID。
- Instant ID 的关键点与特征嵌入预处理器分别绑定官方对应模型；单个控制单元不等同于专用模板中身份图、姿态图组成的完整换脸流程。
- 主体参考的官方示例需要专用模板和 `unitOrder=0`；光影、二维码尚无已核实的对应预处理器，Revision 尚无官方 API 映射。这些类型显示限制并禁止执行。Qwen Image 模型仅留目录，当前 SD / F.1 适配器不执行其模板。

任务提交校验未知键、缺失参数、范围、整数、类型和模型兼容关系。Canny 与其他预处理器参数不能混用。已保存的类型、预处理器与参数恢复后保持原值，不会被重写为 Canny；任务快照继续冻结当时有效参数。

## 复用与扩展合同

画布持久合同为 `GenerationSpec.options.controlNet` 与 `options.outputMask`。引用分别使用 `control-image`、`control-mask`、`output-mask` 角色，普通引用保留 `reference`，局部重绘另使用 `mask`。输出蒙版不会自动开启局部重绘。未配置完的节点可保存草稿；生成任务会严格拒绝缺失图片、控制模型或非法参数。

任务提交使用顶层 `controlNet[]`、`outputMask` 和独立的重绘 `mask`：每个控制单元包含稳定 ID、图片资源、可选区域蒙版和通用参数。`outputMask` 包含图片、灰度/非黑模式及显式 `resizeMode: "stretch"`。资源必须先入库为 `resource:` 引用，服务端在入队前校验归属并读取图片真实字节，拒绝损坏、超限或伪造尺寸的图片。通用控制输入接受 PNG/JPEG、单图不超过 10 MB、每边不超过 4096；快捷入口的透明 PNG 约束不改变通用控制图格式。

模型能力通过 `image.controlNet` 声明 `supported`、`maxUnits`、`preprocessors`、`baseModel`，以及可选 `models` 白名单和 `modelCatalog` 自定义目录。已有显式预处理器白名单保持不变；升级代码不会自动为管理员只开放 Canny 的模型启用所有类型。逻辑路由使用独立的 `control_image` 输入数量，普通图片模型不会接收后静默忽略控制图。协议适配器还必须明确声明并实现 ControlNet；仅修改前端渠道名称或能力布尔值不足以执行。

如果 Dream Tech XL 仍保留旧的 Canny-only 配置，可使用 `scripts/sql/enable-liblib-sdxl-controlnet.sql` 显式升级。该脚本仅匹配已启用的指定 SDXL checkpoint，设置 SDXL 底模及官方推荐的 46 个预处理器，对应 11 类兼容控制组合；不会为 SDXL 开放仅适用其他底模的模型。执行前备份，并用 `expected_capability_version` 指定读取的能力版本，先加 `dry_run=true` 回滚演练；正式完成后递增路由目录缓存版本。其他模型、价格与渠道配置不变，后续管理员自定义配置不被覆盖。

新增平台时复用相同节点、引用、资源校验与最终蒙版合成，只新增平台协议适配、媒体准备和兼容模型目录。平台专有字段保留在各自 `providerOptions` 命名空间，通用契约不包含 AK/SK、签名或上传临时凭证。

## Liblib 协议

安装官方 `liblib-image` 插件后，在渠道中选择「Liblib 图片与 ControlNet」，配置 AccessKey 与 SecretKey，再配置图片模型能力。节点的「生成参数」按插件参数声明显示，`family` 选择 `f1` 或 `sd`，填写当前生成模式对应的 `templateUuid` 与采样步数。`sd` 还需要 checkpoint UUID、采样器枚举和 CFG；图生图需要 `denoisingStrength`。模板与模型 UUID 不使用臆造默认值。

多 Control Type 需要配套的后端校验、前端目录和 `liblib-image 1.2.0` 插件。局部重绘沿用已接入的媒体处理，模型默认仍为 `image.references.maskSupported=false`；管理员确认所用 SD / SDXL 图生图模板支持局部重绘后，才开启该能力。插件升级本身不会替全部模型启用蒙版。

`family=sd` 且同时提供普通内容原图和独立重绘蒙版时，协议使用 `mode: 4`，发送 `maskImage` 及 `inpaintParam`（`maskBlur: 4`、`maskPadding: 32`、`maskMode: 0`、`inpaintArea: 0`、`inpaintingFill: 1`）。普通图生图仍为 `mode: 0`；输出宽高通过 `resizedWidth` / `resizedHeight` 传递，`controlNet[]` 独立保留。

通用重绘的默认 `inpaintMaskMode=alpha` 使用「透明处重绘」语义，后端以 `255 - alpha` 转成供应商所需的灰度 PNG。异形屏上传约定为「不透明处是屏幕」，语义相反，因此快捷入口先派生白色屏内、黑色屏外的蒙版，并显式设置 `inpaintMaskMode=luminance`，由后端按亮度归一化为不透明灰度 PNG：白色重绘、黑色保留。远程蒙版同样读取真实像素后转换，没有可重绘区域时拒绝提交；不能把原始屏幕 PNG 直接当作通用 alpha 重绘蒙版。

### 手工配置 SD 示例模型

不依赖 `/models` 自动发现。`scripts/sql/configure-liblib-sd.sql` 是 PostgreSQL 的显式配置脚本，只对已存在、已启用且保存了 AK/SK 的 `liblib` 系统渠道添加一个模型与价格档，不属于全站自动迁移。脚本按 [liblibai SDK 0.0.11 的接口示例](https://www.npmjs.com/package/liblibai/v/0.0.11)使用基础模型版本 UUID `0ea388c7eb854be3ba3c6f65aac6bfd3`，同时作为产品模型标识和上游模型 ID。本轮已核对官方 ControlNet 表；基础模型与模板的实际可用性仍需分别验证，不能用目录表替代真实上游验证。

脚本采用事务、渠道行锁和现有 `id_sequences` 分配 ID，重复执行不会新增重复模型或价格档；遇到已有配置冲突时终止，不覆盖管理员后续配置。执行前备份目标配置；可先用 `psql -X -v ON_ERROR_STOP=1 -v dry_run=true -f scripts/sql/configure-liblib-sd.sql` 演练并回滚，正式执行去掉 `dry_run`。完成后递增 Redis 的 `canvas:logical-model-route-catalog:version` 使目录缓存失效。脚本不包含密钥，不创建前台模型或线路。

该示例按部署者指定的 **1 积分/张**配置；由于本站图片采用 `fixed_request` 计费，限制每次输出 1 张。上游成本价格保持未配置，不把售价当成供应商成本。尺寸先使用示例的 `768x1024`，未核实兼容控制模型前关闭 ControlNet。

渠道模型可通过 `defaultOptions` 保存平台生成默认值，并下发给创作入口。通用节点允许按需覆盖；异形屏入口从所选渠道读取推荐值，优先使用明确的 `templateUuid`，未指定时才按有无普通内容参考图选择 `imageToImageTemplateUuid` / `textToImageTemplateUuid`。不要把请求模板 UUID 当作基础模型 ID。上述 SD 示例的参数为：

| 参数 | 文生图 | 图生图 |
| --- | --- | --- |
| `family` | `sd` | `sd` |
| `templateUuid` | `e10adc3949ba59abbe56e057f20f883e` | `9c7d531dc75f476aa833b3d452b8f7ad` |
| `steps` / `sampler` / `cfgScale` | `20` / `15` / `7` | `20` / `15` / `7` |
| `seed` | `-1` | `-1` |
| `denoisingStrength` | 不填 | `0.75`，另提供一张普通参考图 |

`checkPointId` 留空时，现有 SD 适配器采用上游模型 ID。历史开发环境已验证该组合的单张文生图、普通图生图、Canny 与输出蒙版合成；横向示例另在渠道允许尺寸中加入 `1024x576`。这些结果不替代新增局部重绘与 ControlNet 组合的真实验收。

### 协议与控制模型边界

基础模型、控制模型和模板必须匹配。API 接口能接收 ControlNet 并不代表其中每个模型都支持同一控制模型；管理员可用 `image.controlNet.models` 缩小节点中的选择范围。切换基础模型时清除旧控制模型标识，要求重新选择。

[Liblib 官方文档](https://resonate.feishu.cn/wiki/UAMVw67NcifQHukf8fpccgS5n6d)的 XL Canny 推荐控制模型为 `xinsir_controlnet-canny-sdxl_V2`，UUID 为 `b6806516962f4e1599a93ac4483c3d23`。彩色分区图作为 `control-image` 输入，保留内部边界；输出蒙版仅负责生成后的外轮廓裁切，不能替代控制图。Canny 提供边缘约束，区域内容仍由提示词描述，精确分区与透视效果需检查实图。

上传控制图时，multipart 的 `file` 部分必须携带由图片真实格式确定的 `image/png` 或 `image/jpeg`。Liblib OSS 的签名策略会校验该类型；Go `CreateFormFile` 默认的 `application/octet-stream` 会被拒绝为 HTTP 403，即使上传签名接口已成功。文件部分的 `Content-Disposition` 中 `name`、`filename` 还必须保留双引号；真实 OSS 会将不带引号的形式拒绝为 `MalformedPOSTRequest`。文件保持最后一个表单域，AK/SK 不发送给 OSS。真实上传复现与修正验证见待测试记录。

Liblib 的生成请求包装为 `templateUuid` 与 `generateParams`；控制数组映射到 `generateParams.controlNet`。`sourceImage` 使用供应商可访问的 URL，单元 `width`、`height` 是真实控制图尺寸，输出尺寸另行传递。

文生图、图生图与查询复用现有异步任务宿主。查询中的状态 3（已生成）和 4（审核中）仍在运行，只有状态 5 才进入结果保存；状态 6/7 为失败/超时。已受理的任务恢复时继续查询原 `generateUuid`，保存失败走原有资源恢复流程。

签名由服务端按实际 URI 路径、毫秒时间戳和随机 nonce 计算 HMAC-SHA1，再编码为无填充 Base64URL。AK/SK 使用现有受管渠道密钥存储；每次提交、查询和上传授权单独签名。第三方图片上传凭证只用于授权的上传请求。

上传走 Liblib 上传授权及 OSS PostObject。字段映射依据 Liblib 上传说明与 OSS V4 标准；其真实账号返回格式、文件可访问性和过期行为保留为联调项目。不得把临时上传凭证、签名 URL 或密钥写入公开任务结果。

## 科幻超跑示例与复现

「使用科幻跑车示例」填入一辆银白色科幻超跑跨越转角、从深蓝空间舱冲出的描述，以及对应推荐参数。完整提示词和避免内容以 `web/src/lib/canvas/irregular-screen-example.ts` 中的 `screenCarExample` 为准，避免文档维护另一份长提示词。按钮只填表，保留当前模型、输入素材和生成方式，不发起生成或扣费；推荐值仍需与实际模型核对。

1. 准备目标转角屏的透明 PNG：屏外透明，两侧屏面不透明，共享同一转角。上传后核对原始图、有效区域、像素尺寸与实际屏幕比例。
2. 选择可用的基础模型与 Control Type。示例原有调参以 Canny 为起点，不适用于所有预处理器。选择「图生图」时必须添加内容原图；需要蒙版重绘时，先由管理员确认模板并开启蒙版能力，再上传与屏幕蒙版宽高完全相同的内容原图，并在高级设置中开启「蒙版重绘」。
3. 选择模型支持的同比例输出尺寸，再点击「使用科幻跑车示例」，展开高级设置核对参数。输入可大于输出，但不得因输出尺寸改变屏幕比例。
4. 核对下表、模型价格与预计消耗后，手动点击生成。保存任务与结果，并按下述标准验收；调整参数后另存一组记录以便比较。

| 设置 | 示例值 |
| --- | --- |
| 细节迭代次数 / 画面生成方法 / 描述贴合程度 | `20` / sampler `15` / CFG `7` |
| 复现种子 | `20261022` |
| 画面变化幅度 | `0.75`，使用内容原图时生效 |
| 轮廓约束强度 | `0.6` |
| 开始 / 结束控制时点 | `0` / `0.6` |
| 轮廓识别精细度 | `512` |
| 边缘灵敏度下限 / 上限 | `100` / `200` |

每次记录基础模型 ID、checkpoint 与版本、控制模型 ID、模板 UUID、插件版本、生成方式、输入文件及像素尺寸、输出尺寸、提示词版本或修改后的全文、种子和全部参数，以及任务与结果标识。保留原始输入文件，必要时记录文件哈希；相同种子只辅助在相同配置下比较，不能保证跨模型、跨版本或跨平台得到相同图片。

验收时检查：只有一辆完整连续的车，车头、车尾、车轮与底盘衔接合理；两侧屏面共用站在外转角下方的低机位视点，车身与光带跨越转角时没有分屏、复制或断裂；近大远小、遮挡、接触阴影与光源共同形成纵深；屏外为纯黑，输出比例与屏幕一致，无建筑外框、人物、文字或水印。真实屏幕上的透视与裸眼立体效果还需在目标观看位置验收，提示词、Canny 和蒙版合成都不自动完成屏幕校准。当前示例的目标模型生成质量与真实浏览器流程仍待验收。

## 保存与恢复

输出蒙版在下载生成结果后、注册正式资源前执行，结果保存为无损 PNG。保存检查点同时记录新暂存文件和 `outputMaskApplied`；只有检查点保存成功才清理原图。重复恢复不会再次乘灰度蒙版；暂存文件失效而重新下载原始结果时会重新合成。

任务保存冻结资源引用与参数。恢复原任务继续使用该快照；画布重新生成则使用当前节点草稿。复制节点组时重映射其中的控制图引用，新版本与批次子图保留结构控制配置。
