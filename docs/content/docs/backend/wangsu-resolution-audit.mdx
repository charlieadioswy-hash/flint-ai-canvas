# Wangsu 分辨率核查与修复

核查覆盖开发、生产各 20 个已配置模型，包含停用记录：7 个图片、6 个视频、7 个文本模型。先核对官方详情和 API 文档，在缺失或冲突处实测。文本模型没有媒体输出分辨率。

官方来源为 [模型目录](https://doc.model-store.ai/cn/docs/api/model) 和匿名详情接口 `GET https://doc.model-store.ai/api/aisite/v1/model-plaza/detail?modelId=<model-id>&lang=zh_CN`。共享接口、型号专属说明和真实调用分别记录，不把其他型号的上限套用到当前型号。

## 调用链修复

- `allowCustom=true` 只允许自定义尺寸，不代表提交比例。原生或自定义像素按本模型校验；实际提交比例且上游要求像素时，才要求该档位的明确换算表。
- 普通 `quality=low/medium/high` 保持质量语义。独立 `imageResolution` 优先，贯穿控件、逻辑模型投影、报价、任务快照和协议编码，切换模型时重新校验。
- Wangsu Gemini 原生使用 `aspectRatio + imageSize`，不需要像素换算表。旧字面 `quality=1k/2k/4k` 在读取边界迁移，普通质量不迁移；原价格档继续按明确分辨率匹配，不改售价。
- Gemini 声明式协议与手写回退均排除布尔 `thought:true` 图片，保留所有候选的最终图，不按第一张、最后一张或请求数量猜测产物。
- Hailuo 按时长、分辨率、输入模式组合校验；512P/10 秒例外仅限 Hailuo 02 首帧图生。

生成源、manifest、接口文档及插件包同步更新：Wangsu `1.0.1`、Google Gemini Image `2.1.1`。Wangsu 保留现有参数合同，没有额外迁入 typed `imageParameters`；Google Gemini 原有 typed 合同保留。

## 两阶段配置

第一阶段已在开发、生产执行：备份、事务预演、写入、回读比较并刷新目录缓存。开发更新 Fast 和 Nano 两个模型；生产额外修正 Hailuo 2.3，共三个。再次预演均为零行变化，价格档、启停、密钥和供应商默认值未修改。

第二阶段必须先发布本轮前后端及新版 Wangsu 插件，再迁移 Gemini 独立分辨率、Nano 新比例、Kling 分辨率和比例。目前仅准备脚本，未对旧服务执行；本地修复不代表线上缺陷已经消失。

仓库 `scripts/sql/backup-wangsu-capabilities.sql` 备份相关能力路径；`repair-wangsu-capabilities-core.sql` 执行第一阶段；`repair-wangsu-capabilities-native-resolution.sql` 执行第二阶段。说明见同目录 `repair-wangsu-capabilities.md`。默认回滚；第二阶段还要求显式确认代码及插件就绪。遇到审计外的自定义配置会中止。
