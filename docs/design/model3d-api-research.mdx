# 3D 生成节点：Tripo API 与交互调研

> 范围：文本、单图、多视图生成 3D 模型及原生模型文件下载；首期供应商为 Tripo。
> 性质：官方协议研究、配置建议与验收依据，不表示真实 API 已验收。
> 首期边界：生成与下载。部件拆分／补全、绑骨与动画的后续合同见第 9 节；外部模型导入、重新贴图与重拓扑仍不在本轮实现内。

## 1. 接入结论

首期直接采用 Tripo v3 REST 合同，默认固定 `v3.1-20260211`。ComfyUI 可作为模式选择、视图端口和结果组织的参考，其 Python 生成流程仍主要使用 V2，不能直接复制为 V3 请求。新旧 API 的密钥通用，但 V3 已将通用任务端点拆为按能力命名的端点，模型字段为 `model`，请求体无需 `type`。[官方迁移指南](https://developers.tripo3d.ai/zh/docs/migration-v2-to-v3)、[SDK 支持矩阵](https://developers.tripo3d.ai/zh/docs/sdk)

本节之后明确区分官方事实、实施建议和待实测项。价格是文档估算，示例响应中的 `credits_consumed: 100` 不是实际报价。

## 2. 三种生成模式与上传合同

全局 Base URL 为 `https://openapi.tripo3d.ai/v3`，使用 `Authorization: Bearer {api_key}`。生成请求编码为 JSON；图片上传使用 `multipart/form-data`，由客户端生成 boundary。[认证](https://developers.tripo3d.ai/zh/docs/authentication)、[文件上传](https://developers.tripo3d.ai/zh/docs/files)

| 操作 | 路径 | 关键输入 | 成功创建结果 |
| --- | --- | --- | --- |
| 图片上传 | `POST /files` | 二进制字段 `file` | `data.file_token` |
| 文本生成 | `POST /generation/text-to-model` | `prompt`、`model` | `data.task_id` |
| 单图生成 | `POST /generation/image-to-model` | `input`、`model` | `data.task_id` |
| 多视图生成 | `POST /generation/multiview-to-model` | `inputs`、`model` | `data.task_id` |
| 查询任务 | `GET /tasks/{task_id}` | 任务 ID | `data` 为状态与结果 |

成功信封是 `{ code: 0, data: ... }`；必须同时检查 HTTP 状态和业务 `code`。`task_id`、`file_token` 应作为不透明字符串保存，不按示例中的 `task_` / `file_` 前缀校验。

- 文本：`prompt` 最多 1024 字符；可选 `negative_prompt` 最多 255 字符，支持几何种子 `model_seed` 和内部参考图种子 `image_seed`。[文本接口](https://developers.tripo3d.ai/zh/docs/generation-text-to-model/standard)
- 单图：`input` 可为上传 token、公开图片直链或 Tripo 图像生成任务 ID。生成页列 PNG、JPEG、WebP，最大 20 MB，推荐至少 256 × 256；上传页仅列 JPEG、PNG。首期上传按 JPEG/PNG 处理，WebP 需转换或单独核验。[单图接口](https://developers.tripo3d.ai/zh/docs/generation-image-to-model/standard)
- 多视图：正面必填，总计 2–4 张同一物体图片；应保持光照与外观一致。推荐 `inputs` 使用视图键对象数组，顺序无关，每项只有一个 `front` / `left` / `back` / `right`。旧位置数组必须固定四项，依次为正、左、后、右，空视图填空字符串。另支持单元素任务引用数组，但不能与图片写法混用。[多视图接口](https://developers.tripo3d.ai/zh/docs/generation-multiview-to-model/standard)

```json
{
  "model": "v3.1-20260211",
  "inputs": [
    { "front": "uploaded-front-token" },
    { "back": "uploaded-back-token" }
  ],
  "texture": false,
  "pbr": false
}
```

这是多视图请求结构示意，token 需要替换为真实上传结果。应用应先完成全部图片上传，再创建一次生成任务；任一上传失败时不提交不完整的多视图任务。

## 3. 模型与参数约束

H 系列接口列出 `v3.1-20260211`、`v3.0-20250812`、`v2.5-20250123`；概念页还列出 `tripo-v3.1` 等别名。建议固定日期版本。P 系列三种输入均支持 `P1-20260311` 与 `P2-20260801`，后者标记为 preview；首期默认 H3.1 可减少组合验证范围。[H 文本接口](https://developers.tripo3d.ai/zh/docs/generation-text-to-model/standard)、[模型版本](https://developers.tripo3d.ai/en/docs/models-and-versions)、[P 文本接口](https://developers.tripo3d.ai/zh/docs/generation-text-to-model/p)

| 参数 | 官方约束与默认值 | 首期配置建议 |
| --- | --- | --- |
| `texture` / `pbr` | 均默认 `true`；`pbr=true` 强制开启贴图 | 关闭贴图时同时关闭 PBR |
| `face_limit` | 省略为自适应；H3.1 标准上限 150 万、超清 200 万；H3.0 为 100 万 / 200 万；H2.5 为 50 万 | 空值表示自适应，不发送 `0` 或 ComfyUI 的 `-1` |
| `geometry_quality` | `standard` / `detailed`；H3.0+ 有效 | 默认标准；切换时更新费用提示 |
| `texture_quality` | `standard` / `detailed` / `extreme`；`fast` 需指定新贴图版本 | 默认标准，贴图关闭时隐藏相关配置 |
| `texture_version` | H3.x 默认为 `v3.0-20250812`；`fast` 需要 `v3.5-20260815` | 选快速贴图时显式指定 3.5，切换旧版本后阻止无效组合 |
| `delight` | 默认开启，仅贴图 `v3.5-20260815` 生效，旧版本忽略 | 仅开启贴图并选择 3.5 时显示；离开此组合清除字段 |
| `quad` | H 系列开启后强制输出 FBX；不传面数时默认 1 万，上限 15 万 | 作为高级选项并明确输出格式变化 |
| `smart_low_poly` | 三角面 500–20000、四边面 500–10000 | 与普通面数范围分开校验 |
| `auto_size` | 默认关闭；开启后以米调整现实尺寸 | 高级选项 |
| `compress` | V3 使用字符串 `geometry` | 不沿用 ComfyUI 布尔值 |
| `export_uv` / `export_orientation` | UV 默认开启；导出朝向默认 `+x` | H2.5 仍展示；开关显示与省略字段的默认行为一致 |
| `model_seed` / `texture_seed` | 可选整数；未指定时随机 | 高级选项；不把固定种子当请求幂等 |

上表共同参数依据[单图 H 接口](https://developers.tripo3d.ai/zh/docs/generation-image-to-model/standard)。单图还支持 `enable_image_autofix`；单图和多视图支持 `texture_alignment=original_image/geometry`、`orientation=default/align_image`，后者仅在贴图开启时生效。[多视图 H 接口](https://developers.tripo3d.ai/zh/docs/generation-multiview-to-model/standard)

P1 面数为 50–20000；P2 三角面为 48–50000，四边面为 48–25000。P 系列仅 P2 支持四边面，不应套用 H 系列所有高级参数。[单图 P 接口](https://developers.tripo3d.ai/zh/docs/generation-image-to-model/p)、[多视图 P 接口](https://developers.tripo3d.ai/zh/docs/generation-multiview-to-model/p)

普通 H 模式的面数下限、种子上下限没有查到明确公开合同。`generate_parts` 有额外参数冲突，并超出首期范围，不纳入界面。

## 4. 异步状态、结果与重复提交

任务状态按 `queued`、`running`、`success`、`failed`、`cancelled`、`banned`、`expired` 处理。`progress` 为 0–100；成功结果在 `output.model_url`，预览在 `output.rendered_image_url`；失败可带 `error_code`、`error_message`。任务查询页未列出 `banned/expired`，生命周期页和官方 SDK 已列出，不能无限等待这两个状态。[任务查询](https://developers.tripo3d.ai/zh/docs/task-query)、[生命周期](https://developers.tripo3d.ai/zh/docs/task-lifecycle)

官方建议每 1–2 秒查询，可采用 2 秒；建议轮询超时例如 5 分钟，超时后保留任务并提示稍后查看。客户端停止等待不代表供应商已取消任务。未确认独立取消端点，不应承诺停止等待会退费。

V3 快速入门说明模型下载 URL 在 5 分钟后过期。成功后应立即保存到应用资源存储；签名下载请求不附加供应商 Authorization。链接失效时重新查询原任务获取链接，不能重新生成模型。原生结果通常为 GLB；H 四边面模式为 FBX。[快速入门](https://developers.tripo3d.ai/zh/docs/quick-start)、[SDK 下载说明](https://developers.tripo3d.ai/zh/docs/sdk)

未查到创建任务支持幂等键、相同输入去重或重复请求免计费的承诺。建议本地任务创建只提交一次；取得上游 ID 后立即持久化，后续恢复仅查询。网络超时或响应丢失属于结果不明，不自动再次 POST。查询与下载可有限重试，用户主动重新生成才创建新任务。

限流按 API Key，生成并发按账户和类别。H 默认并发 10、P 默认 5；限流专题区分 HTTP 429 / `1007` 和并发满 HTTP 429 / `2000`，错误处理页则将 `2000` 概括为速率限制，因此不据单页推导完整错误码表。查询重试优先遵循 `Retry-After` 或 `X-RateLimit-Reset`；生成 POST 不自动重试。400/401/403 直接拒绝；本期安全诊断保留 HTTP 状态与数字上游错误码，不透传原始错误描述、修复建议或请求追踪字段，日志不能保存密钥或签名 URL。[限流](https://developers.tripo3d.ai/zh/docs/rate-limits)、[错误处理](https://developers.tripo3d.ai/zh/docs/error-handling)

## 5. 行业交互参考与配置设计

| 维度 | Tripo V3 | Meshy | 对影策的建议 |
| --- | --- | --- | --- |
| 文本流程 | 一次提交可选几何、贴图、PBR | 文本 preview 生成几何，再 refine 上贴图 | 首期保持一个生成命令，未来以供应商能力描述分阶段任务 |
| 多视图 | 2–4 张，正面必填，显式视图键 | 1–4 张；当前 7.1 首图为正面，其余顺序不限 | 数据保存图片角色，不仅保存数组次序 |
| 参数组织 | 几何、贴图、面数、种子 | 几何分辨率、贴图分辨率、拓扑、格式分别配置 | 常用区保留输入、模型、贴图、质量、面数；种子放高级区 |
| 文件下载 | 原生结果；其他格式经独立转换任务 | 按目标格式返回多个模型 URL | 首期下载原生结果，不默认追加付费格式转换 |

来源：[Meshy 文本](https://docs.meshy.ai/en/api/text-to-3d)、[Meshy 多图](https://docs.meshy.ai/en/api/multi-image-to-3d)、[Meshy 单图](https://docs.meshy.ai/en/api/image-to-3d)。这些是交互与合同参考，不代表首期接入 Meshy。

官方 ComfyUI 将三种模式放在同一个 Generate 节点，图片有正、左、后、右端口；下载文件输出与供应商任务上下文输出分开，预览是下游节点。影策可借鉴模式与端口组织，在节点中显示预览、进度和下载入口。ComfyUI 的 `MODEL_INFO` 会携带 API Key，影策不能将该结构写入可持久化、可分享的画布。[ComfyUI 节点](https://developers.tripo3d.ai/zh/docs/comfyui-nodes)

建议供应商配置描述协议版本、Base URL、认证、模型 ID、支持模式、图片数量/角色、参数范围和默认值；节点保存所选模型与参数，结果保存产出模型、供应商任务 ID 和本地资源 ID。更改参数不能自动提交新任务。凭据通过已有受控渠道配置解析，不能成为节点、任务正文、URL或日志字段。

## 6. 文档漂移与实施注意

| 差异 | 已观察事实 | 处理方式 |
| --- | --- | --- |
| 上传格式 | 上传页仅 JPEG/PNG，生成页另列 WebP | 首期严格上传类型或转换，WebP 单列实测 |
| 任务 ID | 文档既有 `task_` 示例也有 UUID | 按不透明字符串保存 |
| 模型别名 | 概念页使用别名，接口页使用日期版本 | 固定接口页版本 |
| 下载有效期 | 新 V3 快速入门为 5 分钟，旧 FAQ 为 60 秒 | 及时落库，不依赖临时 URL 长期可用 |
| 返回示例 | 单图、多视图示例仍有 `type=text_to_model`，费用示例普遍为 100 | 不据示例推导类型校验和报价 |
| Go SDK 输入 | 当前源码调用 V3 路径但仍序列化 `file/files/original_task_id` | 采用当前文档的 `input/inputs`，独立核验请求 |
| SDK 重试 | Go SDK 所有 method 共用网络/5xx 重试，默认额外 2 次 | 不将 SDK 行为当幂等保证；若使用，显式关闭创建重试 |

尚未确认：实际响应的全部可选输出、模型下载 MIME、token/任务保留时间、服务端创建幂等、取消接口、普通 H 面数与 seed 数值边界，以及 P 系列最终收费档位。没有公开合同的能力不对用户作保证。

### 本轮请求与返回复核

用户要求暂缓真实 API 验证，本轮仅访问公开文档并运行离线测试，不读取密钥，不查询余额，不执行上传或生成。当前核对范围是上表三个 H 生成接口、普通文件上传、任务查询及错误信封。

| 合同边界 | 实现选择与复核结果 |
| --- | --- |
| 请求字段 | 三模式端点及 snake_case 映射一致；单图使用上传 token，多图使用具名视图对象数组；不发送旧 SDK 的 `file/files` |
| 贴图与 PBR | 官方均默认开启；应用 API 有意要求两项显式布尔值，缺失/null 拒绝，纯几何显式传 `false,false` |
| 可选参数 | 省略保留上游默认；修正 UV/去光照的默认显示、去光照版本依赖及 H2.5 的 UV/导出朝向入口；种子不擅加非负限制 |
| 成功信封 | HTTP 成功且存在整数 `code=0`、非空 `data` 才解析；缺失/null/字符串 code 不按成功处理 |
| 上传与创建 | 读取 `data.file_token` / `data.task_id` 并校验有效字符串；创建响应不明时保留未知状态，不重发 POST |
| 查询与产物 | 消费 `data.status/progress/error_code/output.model_url`；支持生命周期列出的全部终态；成功但无模型 URL 不能进入本地成功态 |
| 可选返回 | `rendered_image_url`、`credits_consumed`、供应商时间字段暂不进入应用投影；允许其出现，不依赖示例费用或类型字符串 |
| 错误信封 | 非 2xx 也提取数字 `code`；无有效 JSON 时保留 HTTP 诊断；上游原始文本不进入用户结果 |

返回字段依据[上传合同](https://developers.tripo3d.ai/zh/docs/files)、[查询合同](https://developers.tripo3d.ai/zh/docs/task-query)与[错误合同](https://developers.tripo3d.ai/zh/docs/error-handling)。多视图“纯几何”示例只写 `texture=false`，与同页 `pbr` 默认开启并强制贴图的说明有歧义；应用继续显式关闭两项，以参数说明为准。[多视图合同](https://developers.tripo3d.ai/zh/docs/generation-multiview-to-model/standard)

本轮确认的是文档合同与代码映射；供应商真实产物、额度扣费和线上返回差异仍留待真实验收，不能由离线样例推定通过。

## 10. FBX / ABC 导出可行性（2026-11-02 调研）

结论：现有 GLB / GLTF 可以作为 FBX 与 Alembic（`.abc`）的转换来源。FBX 适合模型、骨架与动作交换；ABC 适合静态模型或烘焙后的动画几何缓存。两者不能承诺相同的数据保留范围。OBJ / STL 也可转出静态模型，但无法补回源文件已经丢失的贴图、骨架或动作。

本节保留实现前的调研基线。现已按用户选择实现原生 FBX 直下及按需 Blender FBX／ABC 转换，并使用 Blender 4.5.3 完成静态模型、骨骼动作、内嵌贴图和 UV 的转换回读；未提交付费供应商转换。当前入口、部署与验证范围以 [3D 工作流](../content/docs/backend/model3d-workflow.mdx) 和 [待测试](../content/docs/progress/pending-test.mdx) 为准，Linux 镜像及实际目标 DCC 兼容性仍待验收。

### 实现前基线

| 能力 | 当前事实 | 代码依据 |
| --- | --- | --- |
| 输入与预览 | GLB / GLTF / FBX / OBJ / STL；自包含文件，单文件不超过 128 MiB | `web/src/lib/model3d-formats.ts`、`web/src/lib/canvas/model3d-preview.ts` |
| 转换导出 | 浏览器使用 Three.js 导出 GLB / GLTF / OBJ / STL；导出类型明确排除 FBX，没有 ABC | `web/src/lib/model3d-export.ts:1`、`web/src/lib/model3d-formats.ts:2` |
| 已有 FBX | 四边面生成可返回 FBX，绑骨与动作允许直接选择 FBX；保存并下载供应商原文件 | `backend/internal/app/model3d_worker.go:139`、`backend/internal/model3d/processing.go:118` |
| 导出入口 | 独立 3D 页与资产下载弹窗复用上述浏览器转换 | `web/src/pages/model3d/model3d-results.tsx:98`、`web/src/pages/assets/asset-model-download-modal.tsx` |
| 后端输出 | 当前校验和文件名映射仅处理 GLB / FBX；没有通用 convert 操作或 ABC 合同 | `backend/internal/model3d/files.go:11`、`backend/internal/model3d/processing.go:70` |
| 执行环境 | 后端镜像未安装 Blender / Assimp / Alembic，部署没有独立转换服务 | `backend/Dockerfile:90`、`docker-compose.deploy.yml` |

因此，“能读取 FBX”“能下载原生 FBX”和“能把任意现有模型导出为 FBX”是三个不同能力；本次需要补的是第三项及 ABC 导出。

下载下拉框没有固定的“FBX”转换选项。“原文件（格式）”中的格式取决于当前文件：普通生成默认显示“原文件（GLB）”；选中实际 FBX 产物时才显示“原文件（FBX）”。四边面生成，或绑骨／动作阶段选择 FBX 输出，可以产生后一种文件；已有 GLB 不会因此自动获得 FBX 下载。

### 转换后的数据保留范围

| 选中版本的实际源文件 | 转 FBX | 转 ABC |
| --- | --- | --- |
| 静态 GLB / 自包含 GLTF | 几何、UV、层级可转换；材质和纹理需映射并验收 | 静态几何、变换、UV、法线可转换；不产生新动画 |
| 有骨架与动作的 GLB / GLTF | 可转换骨架、蒙皮与动作；多动作、插值、朝向及缩放需逐项验收 | 求值并采样为逐帧网格／变换，保留运动效果；不保留可编辑的原骨架与控制器 |
| 已有 FBX | 优先直接下载原文件 | 经解析后导出静态或动画缓存；须验证源 FBX 版本兼容性 |
| 当前浏览器导出的 OBJ | 静态几何与已有 UV／法线；当前导出不附 MTL／贴图 | 静态几何；没有可烘焙的骨骼动画 |
| STL | 静态三角网格；没有材质、UV、骨架和动作 | 静态三角网格 |

表中是格式和工具链支持下的可行性判断，不是本项目已经验证的保真承诺。转换必须读取选中版本的原始文件，不能先导成 OBJ / STL 再转，以免主动丢失信息；也不能用预览中居中、缩放、拆件后的场景替代原模型。

Blender 的 Alembic 导出包含几何采样、UV、法线和面材质分组名称；完整着色器与贴图不随该几何缓存自动迁移。需要外观时另附纹理和材质对应说明。多动作模型应明确动作、帧率、起止时间，一条动作输出一个 ABC，避免把多个动作混在同一时间范围。依据：[Alembic 手册](https://docs.blender.org/manual/en/4.5/files/import_export/alembic.html)。

FBX 的节点材质与 glTF PBR 也不完全等价；透明、金属／粗糙度、扩展材质及形态键不能笼统承诺无损，应以选定转换器版本和目标软件验收结果为准。Blender 4.5 的 FBX 导出源码已包含形态键和相对形态键动画处理，不沿用旧手册中“一律不能导出形态键”的描述。依据：[glTF 导入导出](https://docs.blender.org/manual/en/4.5/addons/import_export/scene_gltf2.html)、[Blender 4.5 FBX 导出源码](https://raw.githubusercontent.com/blender/blender/blender-v4.5-release/scripts/addons_core/io_scene_fbx/export_fbx_bin.py)。

### 无损与接口选择（2026-11-03 复核）

不能把“格式能转换”写成“原模型全部数据无损保留”。几何、UV 和动画效果可以作为保真验收目标；FBX 的材质映射、动作采样和扩展属性需要比较，ABC 的几何缓存也不保留原始可编辑骨架。原文件继续保留，转换结果作为新产物。

Tripo 官方转换合同同样没有全量无损承诺。默认 `bake=true`、`texture_format=JPEG`、`texture_size=4096`，分别涉及材质烘焙、贴图格式和尺寸；源贴图可能被重编码或调整尺寸，这是根据参数含义作出的风险判断，尚未实测。改用 PNG 也只关系贴图编码，不能据此承诺整个模型无损；`with_animation=true` 只声明包含骨骼和动画。依据：[官方转换合同](https://developers.tripo3d.ai/en/docs/models-convert)。

路线取舍应按交付范围决定：已有原生 FBX 直接下载；近期只补 FBX 且希望减少部署依赖，可优先接 Tripo，代价是每次转换费用及上游依赖。如果 FBX 和 ABC 必须同期提供，ABC 仍需另一路线，统一用按需 Blender 可复用同一转换环境，混用 Tripo 并不能消除 ABC 的运行依赖。这是集成成本建议，没有同源模型对比结果证明任一路线必然更保真。

FBX 可以保存三角网格。为了取得扩展名而对已有模型执行四边面重拓扑，会改变模型结构，不能作为无损格式转换；生成阶段直接选择四边面 FBX 则是另一种生成设置。

### 可选路线

| 路线 | FBX | ABC | 成本与适用边界 |
| --- | --- | --- | --- |
| 现有浏览器转换 | 没有对应 exporter | 没有对应 exporter | 不能只补下拉选项；引入其他库需要单独验证格式覆盖与动画保留 |
| 浏览器第三方 FBX 库 | 有候选库 | 不覆盖 | 可保持本地文件在浏览器内转换；骨架、动作和复杂变换需要专项验证 |
| Tripo V3 格式转换 | 官方明确支持 | 官方目标格式未列出 | 可复用供应商异步任务机制；每次转换计费，任意本地文件需要额外上传 |
| 后端 Blender 无界面转换 | 可作为转换工具 | 可作为缓存导出工具 | 可统一覆盖两种格式和本地模型；按任务启动并退出，仍有安装体积、启动及转换资源开销，性能待测 |

`@comfyorg/fbx-exporter-three` 的作者声明支持蒙皮、变换／形态键动画和内嵌 PNG；其 Three.js 版本要求与项目当前版本范围相容。但 `bakeSpaceTransform=true` 仅烘焙顶点和法线，复杂骨架／动画场景需要关闭并验证变换。它是 FBX 的可选路线，尚未在项目中接入，也不解决 ABC。依据：[候选库 README](https://github.com/Comfy-Org/fbx-exporter-three/blob/main/README.md)。

Tripo 的 `POST /models/convert` 接受 GLB / GLTF / FBX / OBJ / STL，输入上限 150 MB；支持 FBX 目标和 `with_animation`。`task_id` 输入只明确列出原始生成任务，已有拆分／动作版本应使用该版本实际文件的上传 token，不能回退到原始生成任务而丢掉后处理。本站现有 128 MiB 上限仍适用。依据：[转换合同](https://developers.tripo3d.ai/en/docs/models-convert)。

官方转换基础 5 积分、高级 10 积分；贴图尺寸／格式等非默认参数可能进入高级档。新绑骨或动作可直接选择 FBX 输出，避免另做一次格式转换。依据：[定价](https://developers.tripo3d.ai/zh/pricing)、[绑骨](https://developers.tripo3d.ai/en/docs/animations-rig)、[动作](https://developers.tripo3d.ai/en/docs/animations-retarget)。

Blender 支持后台运行 Python 脚本，因此可以采用“原文件 → 导入 → 选定动作／采样范围 → 导出”的无界面任务；这是工具支持下的方案建议，仓库尚无对应转换脚本。依据：[命令行参数](https://docs.blender.org/manual/en/4.5/advanced/command_line/arguments.html)。

### 可复用的开源实现

Blender 本身已有开源导入／导出实现，无需自行编写 FBX 或 ABC 文件编码器：GLB / GLTF 导入调用 `bpy.ops.import_scene.gltf`，FBX 导出调用 `bpy.ops.export_scene.fbx`，ABC 导出调用 `bpy.ops.wm.alembic_export`。可直接使用发行包里的实现，由少量 Python 编排代码选择源文件、动作、采样参数和输出文件。依据：[导入接口](https://docs.blender.org/api/4.5/bpy.ops.import_scene.html)、[FBX 源码](https://raw.githubusercontent.com/blender/blender/blender-v4.5-release/scripts/addons_core/io_scene_fbx/export_fbx_bin.py)、[Alembic 网格导出源码](https://raw.githubusercontent.com/blender/blender/blender-v4.5-release/source/blender/io/alembic/exporter/abc_writer_mesh.cc)。

现成批量转换项目可参考 [Transmogrifier](https://github.com/SawyerRensel/Transmogrifier)。其 README 列出 GLB / GLTF、FBX、ABC 等输入输出格式；已核查 `Functions.py` 的格式映射确实调用 glTF、FBX 和 Alembic 对应的 Blender operator，并非仅有格式名称。当前 manifest 为 2.0.0，声明 Blender 最低 3.6、许可证 `GPL-3.0-or-later`。它是批量转换插件，不是本站可直接接入的任务服务；可参考其格式分派、参数预设、纹理与日志流程，实际转换仍依赖 Blender。依据：[格式分派源码](https://github.com/SawyerRensel/Transmogrifier/blob/main/Functions.py)、[项目 manifest](https://github.com/SawyerRensel/Transmogrifier/blob/main/blender_manifest.toml)。

对本站只有 FBX / ABC 两个目标的范围，建议直接封装 Blender 官方 operator，避免引入整套批处理插件及其 UI；这是集成方案选择，不代表插件已完成项目兼容验收。

### 建议实施边界

如果目标是同时支持 FBX、ABC，并覆盖已有生成结果和本地导入模型，可复用现有 Go 任务调度，**按需启动 Blender 命令行子进程，转换完成即退出**。无需常驻 Blender 进程或额外建立转换服务；空闲时没有 Blender 进程内存占用，但仍需安装转换器并承担启动开销。保留原始 GLB / GLTF 作为完整度较高的转换来源；已有 FBX 直接下载。Tripo 转换适合作为只覆盖上游模型、优先交付 FBX 的较小范围方案，不能完成 ABC 需求。

用户只需要格式转换并关注部署重量时，优先保留已有 FBX 原文件下载；GLB 转 FBX 可先验证上述浏览器候选库，ABC 再按需调用 Blender。若进一步要求完全不安装 Blender，可评估模型解析器加 Alembic 写入库，但需自行处理场景、动画求值和蒙皮采样，不等同于直接替换一个文件导出接口。Assimp 官方格式表将 FBX 导出标为实验性，未列 Alembic，不能作为同时覆盖两种目标的直接替代。依据：[Assimp 格式表](https://github.com/assimp/assimp/blob/master/doc/Fileformats.md)、[Alembic 几何库](https://docs.alembic.io/reference/abcg.html)。

需要新增的工作包括：

1. 独立导出任务与产物关联，保留源资源和版本；记录目标格式、转换器版本、动作与采样参数。复用现有任务状态、归属校验、资源存储和失败恢复，不覆盖原模型，也不把本地预览文件未经用户操作自动上传。
2. 固定 Blender 版本，通过可执行文件或任务镜像交付转换依赖，默认不新增常驻服务。已有任务执行器按需调用，初期限制转换并发为 1；每任务隔离临时目录，并设置超时和内存限制。导入仅使用已授权的自包含资源，不解析任意外部依赖。
3. ABC 的格式识别、真实文件校验、资源类别与下载合同；当前 `FileType` 不能直接传入 `abc`，否则会落到 GLB 默认值。导出动画缓存可能超过 128 MiB，应按实测单独制定输出额度，不能直接放宽全部模型限制。
4. 两个下载入口增加 FBX 与“ABC（动画几何缓存）”；ABC 先作为导出产物即可，不要求同步实现浏览器 ABC 预览。材质附件涉及多文件时显式打包，不能伪装成单个含完整材质的 ABC。

### 开发前最小样本验证

| 样本 | 需要证明的结果 |
| --- | --- |
| 有贴图的静态 GLB | FBX 外观、ABC UV／法线与材质分组；对象尺寸、朝向和层级正确 |
| 有骨骼动作的 GLB | FBX 蒙皮与动作可播放；ABC 在起点、中间、终点的顶点位置与源动作一致 |

| OBJ / STL 与已有 FBX | 静态模型可转换且不编造材质／动作；FBX 源版本可导入 |
| 较大动画文件与任务中断 | 测出峰值内存、耗时和体积；中断、重试不覆盖源文件，不交付残缺产物 |

验收应在实际目标 DCC 中重新打开 FBX / ABC；仅检查扩展名、文件头或在同一转换器中回读，不能代替目标软件兼容性验证。本轮已完成的 Blender 回读与自动测试见上方工作流和待测试记录；形态键、较大模型峰值内存及目标 DCC 仍需另行验收。
