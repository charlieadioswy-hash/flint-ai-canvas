# 短剧简易制作流程重构实施计划

状态：开发中。取代短剧 Agent 引导与左侧聊天制作方式，保留详细视频制作台和画布 Agent。按独立功能批次实现、review、验证和提交；未完成事项不因主线可用而视为完成。

## 目标与设计依据

以飞书[短剧设计](https://zv7w2qqgbu9.feishu.cn/wiki/B58PwmcStiu0UZkKKs6ccZWZnQg)的 40 张参考页面组织确定性的创作流程。简易台负责快速上手、成果审阅和明确的下一步；复杂参数仍可进入详细制作台。页面使用影策既有组件、主题和设计 token，不复制参考产品的品牌、供应商名称或示例资产。

正文与资产提取、剧本改编、提示词生成仍调用模型，但不再通过短剧聊天、proposal 或会话推进。保留原文角色说明复用、去重、CAS、计费、任务范围、失败恢复、缺图补齐及合成等已有修复。

参考稿里的授权书单、小说商业授权、转绘出海不是既有短剧流程，本计划不虚构这类外部内容服务。正文项目草稿承担已导入材料的保存与再次打开。其余本次评估涉及的功能全部纳入下面阶段，较大功能延后开发而非删除。

## 页面与状态合同

统一六步：导入正文 → 确认正文与拆集 → 风格和基础配置 → 主体资产 → 分集分镜与视频 → 预览导出。

| 页面 | 内容和主操作 | 后端事实 |
| --- | --- | --- |
| 导入正文 | 小说、剧本、已有分镜；上传 TXT/Markdown/DOCX 或粘贴；解析错误、重传、格式示例 | 创建同一项目草稿，不执行生成 |
| 正文确认 | 集/章节列表、正文编辑、制作范围、先试首集、追加集、正文下载 | configuring；正文不是已完成的 AI 改编稿 |
| 风格配置 | 系统/个人风格、预览样图、模型、比例、分辨率、语言、时长、资产模板 | configuring；确认后启动资产文字提取 |
| 主体资产 | 角色/场景/道具、按集筛选、编辑/新增/导入、图片版本、造型、声音、按需生图 | assets；无图片也能确认文字继续 |
| 分集分镜 | 集/段/镜头、失败集、进度/筛选/队列、编辑、重写、局部或批量视频 | story；文字确认后 completed，视频按显式意图执行 |
| 预览导出 | 每集预览、合成、结果版本、下载、资产包、剪映、跨集操作 | 集、段、job、finalStale 等实际状态 |

页面浏览步骤与执行阶段分开。返回已完成页面不改 GuideStep；后端 readiness、ExpectedRevision 和 ExpectedStep 决定能否保存或推进。阶段字段继续复用，不因名称含 guide 而新建第二套状态机。URL 保存浏览步骤、集/段定位，任务和产物以服务端为准。

简易/详细两台共享项目、集、段、镜头、资产、任务和查询缓存。详细台原 Agent 入口改为简易制作台；旧 guide 路由直接承载新流程。正在配置、资产提取中、分镜失败、已完成及传统项目分别恢复到正确步骤。切换视图不绕过阶段门禁。

## 操作和数据规则

- 媒体按钮直接预检，展示本次目标、缺失依赖、预计费用和实际入队状态；确认时重新验证版本和报价。页面/账号/目标切换后隔离迟到回执，重复点击不重复提交。
- 补图只生成本次缺失资产；完成后重新预检视频并让用户确认。等待上一段尾帧、已排队和执行中具有明确状态，不自动扩大到整集/全剧。
- 正文保存与重新改编分开。保存前列出受影响集，重新改编保留旧媒体历史；资产编辑说明受影响段和尾帧续接范围。风格变化不隐式重写剧本或付费重生媒体。开工后的画幅、分集方式沿用限制。
- 原文有角色定义则原样复用，未明确的信息保持为空。新增仅名称资产可保存；没有生图描述时阻止生成并提示补充，AI 补写是单独确认的文字任务。
- 图片版本、角色造型和同一造型的不同视图分别建模。多视图不能伪装成造型或图片历史；媒体选用和产出模型分别记录。
- 批量操作按真实集/段/资产 ID 预检与执行，返回成功、跳过、冲突、失败明细；局部失败可以局部恢复，不重新生成成功对象。
- 文字阶段第一批按用户选择的集/章节推进；进一步实现按集就绪即可独立推进，失败集不阻塞其他已确认集。
- 不新增通用工作流引擎、第二套项目或任务表。新能力沿用现有资源、任务、计费及存储，只有明确的新媒体归属需要增量数据模型。

## 并行开发和 review

第一组并行：W01 文件导入、W02 媒体操作、W03 后端编辑保护；主任务完成合同和 W04 页面整合。后续按依赖分资产、媒体、流程三个工作包。每个任务显式限定文件所有权，避免同时改同一页面、API 合同和迁移版本。

实际使用本机 Claude CLI 分担实现。每个子任务记录提示、进程、改动列表、检查结果和 review；主任务负责核对代码和需求、修复发现、集成验证、精确暂存和提交。禁止子任务自行发布、提交无关文件或调用真实付费模型。

每批提交格式为 `feat|fix|refactor(drama): 短剧制作 - …`，文档使用 `docs(drama)`。未提交的既有 LoRA、文档、guide-panels 与 guide.css 改动保持原状，不能混入本轮提交。

## 验收与完成证据

- 主流程：小说、剧本、已有分镜分别导入；从正文确认到资产、分镜、视频、合成及导出可完成。
- 原文保真：明确角色设定直接复用，台词不丢失，已有分镜顺序/数量按原文转录；人工修改不被提取重写。
- 状态恢复：刷新、重新登录、两台往返、存量 configuring/assets/story/completed/传统作品均落位正确。
- 并发：旧 Revision、旧报价、多标签保存、快速重复点击、切换账号/对象后的迟到回执不能写错对象或重复入队。
- 媒体：跳过图片、缺图补齐、本体→造型、等待尾帧、视频下载后处理失败、局部重试、批量部分失败均有正确范围和费用。
- 新能力：多视图、首尾帧、镜头媒体、宫格/故事板和音频使用真实任务、资源及采用记录，不能以演示数据替代。
- UI：与参考的信息结构一致且沿用影策风格；明暗主题、键盘、窄屏、滚动、弹窗、长正文和空态可用。
- 回归：详细制作台、画布 Agent、已有任务和历史结果保持可用。
- 各批按风险运行专项测试/类型检查；整合后真实页面浏览器验收。付费媒体调用需明确范围和真实可用测试配置，未执行的路径明确留待验收。
- 所有范围完成并有实现、测试、review、提交及页面证据后，才标记全目标完成。生产部署由用户另行明确发出指令。
